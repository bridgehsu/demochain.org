# 序言与阅读路线

## 为什么按业务流程组织

一个业务动作经常跨越接入、委托、撮合、账户和推送。按目录逐个介绍类，容易丢失状态如何流转的上下文。因此每篇文章先回答：谁触发、处理什么、改变什么状态、结果交给谁。

## 两条主线

- **现货线**：委托接入 → 撮合事件 → 订单簿 → 成交及账户处理 → 行情与用户结果。
- **合约线**：合约委托 → 撮合事件 → 订单簿 → 仓位及保证金相关处理 → 风险与行情。

以上是阅读模型；每一个跨服务箭头都需要用调用方、接口和消息消费者确认。

## 每篇文章的写作结构

业务场景 → 服务边界 → 数据与状态 → 正常流程 → 异常分支 → 源码入口 → 验证方法。

## 阅读顺序

先读服务地图，选一条交易主线，再读账户、行情和运行维护。涉及期权、杠杆、OTC 等扩展时，从平台服务索引进入对应源码，避免混入现货与合约的主链路。
