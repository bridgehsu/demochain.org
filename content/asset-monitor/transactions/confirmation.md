# 确认、超时与失败重试

## 状态观察

Adapter 返回链相关的观测结果，再映射为系统任务状态。应区分待确认、确认成功、明确执行失败、查询不到和节点不可用。确认标准由链及策略配置明确，不能把首次查到回执当作所有链的最终状态。

## 重试分类

| 情况 | 建议动作 |
| --- | --- |
| 元数据或只读查询超时 | 在预算内退避重试 |
| 策略拒绝或参数不合法 | 停止自动重试并记录原因 |
| 广播超时 | 查询原提交上下文，保留 UNKNOWN |
| 等待确认超时 | 继续核对原交易与链状态 |
| 链上明确失败 | 记录失败；重新执行前重做策略和预检查 |

## 费用与有效期

费用变化、交易有效期耗尽和替换提交须交由对应 Adapter 处理，并关联原执行意图。新载荷必须重新校验，不能在通用重试器中盲目提高费用或再次签名。

## 迟到结果

超时处理后仍可能收到回执。建议用状态版本和提交标识判断事件是否属于当前执行，避免迟到失败覆盖已经确认的结果。按链规则处理确认变化，并留存观测历史。

## 验证场景

回执延迟、节点返回冲突、追踪时应用重启、明确失败与查询超时同时出现。重点验证超时不会直接触发重复交易。
