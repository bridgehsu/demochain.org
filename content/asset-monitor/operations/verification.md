# 异常场景与验证清单

## 最小闭环

使用可控测试信号，依次观察接入、地址识别、元数据、策略、预检查、构造、提交与追踪。记录每步输出与状态变化，再确认重放信号不会重复产生同一执行。

## 故障验证矩阵

| 场景 | 期望观察 |
| --- | --- |
| 同一消息并发投递 | 来源保留，执行意图不重复 |
| 地址对应多条候选链 | 保留证据，按明确规则继续或拒绝 |
| 元数据节点超时 | 可重试结果，不误判资产不存在 |
| 费用变化或余额不足 | 在预检查或提交阶段留下明确原因 |
| 节点接收后响应丢失 | 转 UNKNOWN，查询原提交 |
| 回执延迟 | 继续追踪，不直接重复执行 |
| 锁过期且旧 worker 恢复 | 检查执行权与原提交记录 |
| Redis 不可用 | 按预定策略暂停或降级并告警 |
| 广播后应用重启 | 能恢复原交易的追踪 |
| 旧回执迟到 | 不覆盖不相干的新状态 |

## 验证层次

使用 mock 测试超时与状态分支；用本地链或适用的测试网络验证构造、签名、提交和查询；对每个 Adapter 单独记录覆盖范围。未获得测试依据前，不写“所有链均通过”或性能提升数值。

## 上线前补齐

实际源码路径、配置结构、链能力矩阵、确认标准、任务持久化和恢复机制、策略阈值，以及可复现的测试结果。本文是模块文档与验证方案，尚未代表真实节点集成验证。
