# 系统目标与核心流程

## 业务目标

把社交媒体文本和链上事件转换为可识别、可校验、可追踪的任务。信号发现只代表出现候选资产；策略通过只代表允许继续预检查；广播成功也不等于链上执行成功。

## 输入与输出

| 阶段 | 输入 | 输出 |
| --- | --- | --- |
| 信号接入 | 文本、订阅事件、待确认交易线索 | 标准事件与来源信息 |
| 识别与路由 | 地址候选、来源上下文 | 链路候选与识别依据 |
| 校验与策略 | 链上查询、元数据、策略配置 | 通过、拒绝或等待复核 |
| 执行 | 通过预检查的任务 | 构造结果与提交标识 |
| 追踪 | 提交记录、回执、节点查询 | 确认、失败或结果未知 |

## 核心边界

链路识别没有足够证据时保留歧义；外部调用超时时保留未知结果；重试前恢复上下文。这样每一步都能说明为什么继续或停止，而不是用一个布尔值代表整个任务。

## 模块协作

Golang 协程与 Channel 承接异步工作；Adapter 隔离链差异；Redis 用于去重、短周期缓存、状态缓存与执行锁；日志和告警连接来源、任务与交易结果。持久审计存储的具体实现未提供，应在源码核验后补充。
