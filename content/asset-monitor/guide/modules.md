# 模块边界与个人贡献

## 模块职责

| 模块 | 责任 | 主要交接结果 |
| --- | --- | --- |
| 信号接入 | 消费社交媒体消息及链上信号 | 带来源的标准事件 |
| 地址解析 | 提取、归一化、识别与去重 | 链路与资产候选 |
| 多链 Adapter | 节点接入、查询、构造与提交 | 链相关查询和执行结果 |
| 策略调度 | 校验、状态推进、重试和超时处理 | 可追踪的策略任务 |
| 结果追踪 | 查询交易、处理确认与失败 | 结果状态和原因 |
| 运维追踪 | 日志、告警与复盘关联 | 问题定位上下文 |

这是逻辑模块划分，不要求每个模块独立部署。

## 个人贡献

按负责人提供的信息：独立负责系统核心链路设计与开发，完成社交媒体信号接入、CA 地址解析、多链 Adapter 抽象、节点 RPC 对接、策略任务调度、交易状态追踪、失败重试和告警通知，支撑多链资产监测与自动化策略执行闭环。

## 后续源码补充

每个逻辑模块补充实际目录、入口函数、上下游接口及验证记录。吞吐量、延迟、链覆盖程度和收益等量化指标须提供测量依据后再写入；目前不作数值声明。
