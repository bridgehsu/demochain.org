# 区块结构

区块（Block）是区块链的基本存储单元，每个区块就像账本的一页，记录着一批交易数据。

## 区块包含哪些字段

| 字段 | 说明 |
|------|------|
| **高度（Height）** | 区块在链中的序号，从 1 开始递增 |
| **数据（Data）** | 区块打包的交易内容 |
| **随机数（Nonce）** | 矿工用于调整哈希结果的可变数字 |
| **前驱哈希（Prev Hash）** | 上一个区块的哈希值，形成"链" |
| **哈希（Hash）** | 对本区块所有字段计算得到的指纹 |

## 哈希如何计算

区块的哈希是对以下内容做 SHA256：

```
Hash = SHA256(高度 + 数据 + Nonce + 前驱哈希)
```

任何字段的改变都会导致哈希完全不同。这就是区块防篡改的根本原因。

## 什么是"有效区块"

一个区块被认为有效，需要满足：

1. **哈希满足难度要求**：哈希开头有规定数量的零
2. **前驱哈希正确**：指向上一个区块的哈希
3. **数据合法**：交易签名有效，没有双花

第 1 条是矿工挖矿时需要耗费算力完成的工作。

## 挖矿过程

```
1. 收集待打包的交易
2. 构建区块头（高度、数据、前驱哈希、Nonce=0）
3. 计算 SHA256 → 检查是否满足难度
4. 不满足 → Nonce + 1 → 重新计算
5. 满足 → 广播区块，等待网络确认
6. 获得区块奖励（币基交易）
```

## 修改数据会发生什么

如果有人尝试修改某个区块的数据：

1. 该区块的哈希立刻改变（雪崩效应）
2. 下一个区块记录的"前驱哈希"对不上了 → 下一个区块失效
3. 后续所有区块都需要重新计算 → 需要重新消耗大量算力

这就是链式结构带来的不可篡改性。

## 在演示中体验

在区块演示页面，你可以：
- 修改区块数据，实时看到哈希如何变化，区块变为"无效"状态
- 点击"挖矿"按钮，观察 Nonce 不断增加直到找到有效哈希
- 调整难度，感受挖矿时间的指数级变化
